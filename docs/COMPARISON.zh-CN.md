## 与 Tabby 的定位差异

Tabby 是通用终端方向:强在终端标签页与分屏、主题/配色自定义和插件生态、多协议
(Telnet/串口)与跨设备配置同步。DBX SSH & SFTP 的差异集中在服务器运维链路:

- 认证与提权编排更强:全局 Quick Sudo 档案、TOTP/2FA 自动应答、sudo 白名单、只读
  门禁和宿主 secret binding 全部内置;Tabby 通常依赖插件或脚本。
- 内置 31 个 MCP 自动化工具,AI 客户端可在同一连接与权限边界内操作服务器。
- 会话录制/回放与 GIF 导出、跨会话批量发送命令、断点续传、Zmodem/Trzsz 为内置。
- 最多三跳 ProxyJump,逐跳独立认证、2FA 与主机密钥校验。
- 端口映射 -L/-R 已内置(0.6.0);X11 转发已实现(默认关,2026-09-24,merge 75c5219);
  动态 SOCKS 隧道、agent forwarding、GSSAPI 与 ControlMaster 有意不做,分别由宿主
  传输层覆盖或按产品决策让渡。
- 终端分屏归宿主工作台;终端外观默认跟随宿主,另有 192 套内置配色可选覆盖;
  Telnet/串口/VNC 已全栈落地,RDP 仍在人工评审门。

## DBX 插件家族中的位置

| 插件 | 主要对象 | 适合任务 |
| --- | --- | --- |
| DBX SSH 终端 | SSH 主机、终端、SFTP、远程运维 | 登录服务器、执行命令、浏览与传输文件 |
| DBX Files | 文件系统与对象存储 | 文件浏览、上传下载、归档和跨存储整理 |
| DBX LDAP | LDAP 目录 | 查询、统计、编辑目录条目 |
| DBX Kafka | Kafka 集群 | Topic、消息、消费组和 Schema 运维 |

SSH 终端不重复实现文件、LDAP 或 Kafka 的专用协议；它专注于“通过 SSH 到达主机后
进行终端和 SFTP 运维”，并通过 DBX 宿主能力复用连接、密钥和工作台桥接。

## 如何选择

- 只需要脚本化 SSH：选择 OpenSSH；它最轻量，自动化边界由 shell 和系统策略负责。
- 需要漂亮的终端标签页、分屏和主题自定义：Tabby 是通用终端方向；其安全策略取决于插件/配置。
- 需要跨设备连接同步：Termius 更偏商业化跨端体验，具体功能取决于版本和计划。
- 需要 SSH、SFTP 和服务器状态放在一个桌面工具：FinalShell 是直接替代方案之一。
- 已在 DBX 中使用宿主连接、MCP 或插件工作台：DBX SSH & SFTP 能把这些能力放在
  同一套连接和权限边界内。
- 需要 RDP 或更多协议：可以关注 DBX 后续版本；Telnet/串口/VNC 已内置，RDP 仍在
  评审推进，建议按具体版本的发布说明验证。
